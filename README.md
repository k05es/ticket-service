# ticket-service

Информационная система для работы с заявками пользователей.

Клиенты создают заявки на решение проблем, специалисты берут их в работу 
и устраняют проблемы. 
Распределение заявок между специалистами происходит автоматически: 
класс `TicketQueueProcessor` использует пул потоков 
для параллельной обработки очереди необработанных заявок.

Проект выполняется в рамках лабораторной работы № 1 
по дисциплине «Программирование кроссплатформенных приложений». 

На данном этапе данные хранятся в оперативной памяти с использованием 
коллекций Java, без подключения базы данных.

## Технологии

- Java 17
- Spring Boot 4.1.1
- Maven
- JUnit 5

## Структура проекта

```text
src/main/java/com/k05es/ticketservice/
├── model/                         # Сущности предметной области
├── service/                       # Интерфейсы и реализации сервисов
├── concurrent/                    # Многопоточная обработка заявок
└── TicketServiceApplication.java  # Точка входа в приложение
```

### Пакет `model`

Содержит классы и перечисления, описывающие предметную область:

- `User` — абстрактный базовый класс пользователя.
- `AdminUser` — пользователь с ролью администратора.
- `SpecialistUser` — специалист, обрабатывающий заявки.
- `CustomerUser` — клиент, создающий заявки.
- `UserRole` — роли пользователей.
- `UserStatus` — статусы пользователей.
- `ContactPreference` — предпочтительные способы связи.
- `TicketStatus` — статусы заявок.
- `Department` — подразделения, к которым относятся специалисты.
- `Permission` — разрешения пользователей.
- `Ticket` — заявка клиента.
- `Message` — сообщение в переписке по заявке.

### Пакет `service`

Содержит интерфейсы сервисов и их реализации, работающие с данными 
в оперативной памяти.

- `UserService` — интерфейс для управления пользователями.
- `LocalUserService` — реализация операций с пользователями:
регистрация, поиск, фильтрация и удаление.
- `TicketService` — интерфейс для работы с заявками.
- `LocalTicketService` — реализация операций с заявками: 
создание, поиск, назначение специалиста и завершение.

### Пакет `concurrent`

- `TicketQueueProcessor` — многопоточный обработчик очереди заявок. 
Использует `ExecutorService`, чтобы организовать параллельную работу нескольких потоков. 
Каждый рабочий поток получает заявку из очереди, назначает специалиста, 
имитирует обработку и завершает заявку.

## Используемые коллекции и средства синхронизации

| Коллекция или класс | Где используется | Назначение |
|---|---|---|
| `HashMap<Long, User>` | `LocalUserService` | Хранение и поиск пользователей по ID |
| `HashSet<String>` | `LocalUserService` | Проверка уникальности логинов |
| `HashMap<Long, Ticket>` | `LocalTicketService` | Хранение и поиск заявок по ID |
| `LinkedBlockingQueue<Ticket>` | `LocalTicketService` | Потокобезопасная очередь заявок |
| `AtomicLong` | Сервисы | Потокобезопасная генерация идентификаторов |
| `AtomicInteger` | `TicketQueueProcessor` | Учёт количества рабочих потоков и обработанных заявок |
| `ExecutorService` | `TicketQueueProcessor` | Управление пулом рабочих потоков |

## Запуск приложения

Для запуска необходима установленная Java 17 
или совместимая более новая версия, 
а также Maven либо Maven Wrapper, включённый в проект.

**Windows (PowerShell):**

```powershell
.\mvnw spring-boot:run
```

**Linux / macOS:**

```bash
./mvnw spring-boot:run
```

После запуска приложения выполняется демонстрационный сценарий: 
создаются пользователи и заявки, запускается обработчик с тремя рабочими потоками, 
после чего результаты обработки выводятся в консоль.

## Запуск тестов

**Windows (PowerShell):**

```powershell
.\mvnw test
```

**Linux / macOS:**

```bash
./mvnw test
```

Тесты предназначены для проверки основных операций с пользователями и заявками, 
включая регистрацию, поиск, назначение специалистов, завершение заявок и обработку очереди.

## Хранение данных

На текущем этапе проект не использует базу данных. 
Данные хранятся в оперативной памяти с помощью коллекций Java 
и доступны только в течение работы приложения. 
После его завершения данные не сохраняются.
